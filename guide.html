내일의 나 · 과학과 나의 진로

3개 반, 반별 25명 수업을 위한 설치 없는 HTML 웹앱입니다.

  • 학생: 이름 선택 → 희망 직업과 이유 → 친구에게 추천 → 추천 결과 → 두 직업의 미래 탐구
  • 교사: 명단 입력, 개인 접속 번호 발급, 단계 개방, 추천 내용 관리, 결과 인쇄·CSV 저장
  • 직업: 8개 분야 × 25종, 총 200종, 도구·활동을 나타내는 그림 문자 아이콘
  • 배포: GitHub Pages / 공용 저장: Supabase

먼저 열어 보기

폴더 전체를 압축 해제한 다음 index.html을 열어 학생 화면 체험 또는 교사 화면 체험을 누르세요.

체험 모드는 가상 학생 25명씩 3개 반을 제공하며, 같은 브라우저에만 저장됩니다. 체험 화면에서는 교사와 학생 역할을 번갈아 접속하여 단계를 바꿔 볼 수 있습니다. 실제 학생 이름은 체험에 입력하지 마세요. 실제 수업에서는 아래 공용 저장소 설정이 필요합니다.

1. Supabase 프로젝트 만들기

  • https://supabase.com/dashboard 에 로그인하고 새 프로젝트를 만듭니다.
  • 프로젝트 준비가 끝나면 SQL Editor를 엽니다.
  • 이 폴더의 backend/setup.sql 파일 내용을 전부 복사해 실행합니다.
  • 결과에 오류가 없어야 합니다. 전용 저장 공간과 수업용 접근 제어가 만들어집니다.

별도 서버 설치나 유료 AI API는 사용하지 않습니다. Supabase와 GitHub의 이용 조건·사용량 한도는 가입한 서비스의 현재 정책을 확인하세요.

2. 교사 계정 등록

  • Supabase의 Authentication → Users에서 사용자 추가 기능으로 교사 이메일과 비밀번호를 등록합니다.
  • 이메일 확인이 완료된 계정이어야 합니다. 사용자 추가 시 자동 확인 항목이 제공되면 사용하거나, 이메일 확인을 완료하세요.
  • 등록한 사용자의 User UID를 복사합니다.
  • SQL Editor에서 다음 코드의 예시 UID를 실제 UID로 바꿔 실행합니다.
insert into career_private.teachers(user_id)
values ('여기에-교사-User-UID를-입력')
on conflict do nothing;

이메일과 비밀번호만 등록하고 위 권한 등록을 빠뜨리면 교사 화면을 열 수 없습니다. 일반 회원가입으로는 교사 권한을 얻을 수 없습니다. 이 앱에 필요한 교사 계정만 관리자 화면에서 만드세요.

비밀번호를 잊으면 Supabase 관리자 화면에서 해당 계정을 관리하세요. 학생은 이메일 계정을 만들지 않습니다.

3. 공용 저장소 연결

Supabase 프로젝트의 연결 정보에서 다음 두 값을 찾습니다.

  • Project URL: https://프로젝트주소.supabase.co
  • Publishable key: 보통 sb_publishable_로 시작하는 공개용 키. 기존 프로젝트의 공개용 anon 키도 사용할 수 있습니다.

config.js를 메모장 등으로 열어 다음처럼 채웁니다.

window.CAREER_CONFIG = {
  supabaseUrl: 'https://프로젝트주소.supabase.co',
  supabaseKey: '여기에-공개용-publishable-key'
};

URL에는 /rest/v1 같은 경로를 덧붙이지 마세요. secret 키나 service_role 키, 교사 비밀번호는 넣으면 안 됩니다. 공개용 키는 화면 연결에 쓰이며, 실제 읽기·쓰기 권한은 제공된 SQL 함수가 검사합니다.

career_private 스키마를 Supabase Data API의 노출 스키마 목록에 추가하거나 학생 테이블의 공개 읽기·쓰기 권한을 열지 마세요. 이 앱은 허용된 수업 API만 사용합니다.

4. GitHub Pages에 배포

  • GitHub에서 새 저장소를 만듭니다. 저장소 이름 예: science-career.
  • Add file → Upload files에서 이 폴더의 내용을 올립니다. 폴더 이름 자체로 한 겹 더 감싸지 말고, 저장소 첫 화면에 index.html이 보이게 올리세요.
  • 최소한 다음 파일을 모두 올려야 합니다.
index.html
style.css
config.js
jobs.js
core.js
app.js
vendor/qrcode.js
vendor/qrcode-LICENSE.txt
  • 저장소의 Settings → Pages → Build and deployment로 이동합니다.
  • Source: Deploy from a branch, Branch: main, Folder: /(root)를 선택하고 저장합니다.
  • 배포가 완료되면 표시되는 Pages 주소를 엽니다.
  • 교사 이메일과 비밀번호로 로그인해 1반, 2반, 3반을 만듭니다.

별도 빌드 명령이나 npm 설치는 필요 없습니다. .nojekyll도 포함되어 있습니다. 소스 코드는 공개 저장소에 올려도 되지만 학생 명단, 접속 번호, 결과 CSV는 저장소에 올리지 마세요.

공식 안내:

  • GitHub Pages 배포 설정: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
  • Supabase 공개용 키: https://supabase.com/docs/guides/getting-started/api-keys
  • Supabase 사용자 관리: https://supabase.com/docs/guides/auth/users
  • Supabase 데이터베이스 함수: https://supabase.com/docs/guides/database/functions

5. 수업 준비

학생 명단

교사 화면에서 학급을 선택하고 학생 명단·현황을 엽니다. 한 줄에 한 명씩 이름을 붙여 넣습니다. 반별 25명 기준이며 최대 40명까지 입력할 수 있습니다.

등록 직후 표시되는 8자리 개인 접속 번호를 인쇄해 개별 배부하세요. 이 번호는 창을 닫은 뒤 다시 조회할 수 없습니다. 잊어버린 경우 접속 번호 재발급을 사용합니다. 재발급하면 그 학생의 기존 접속도 무효화됩니다.

동명이인은 번호로 구분합니다. 이름 수정 시 기록은 유지됩니다. 추천 시작 전 1단계에서 잘못 등록한 학생을 삭제할 수 있습니다. 추천이 시작된 뒤에는 명단과 추천 배정 수를 고정합니다.

참여 안내

참여 안내 복사로 주소와 참여 코드를 복사하거나 참여 QR로 화면을 띄워 주세요. QR 코드는 GitHub Pages 주소에서 사용할 수 있으며 외부 QR 서비스에 정보를 보내지 않습니다.

학생은 반 참여 코드 → 자기 이름 → 개인 접속 번호 순으로 입장합니다. 개인 접속은 8시간 동안 유효하며, 종료할 때 나가기를 누릅니다. 번호를 5회 잘못 입력하면 5분간 재시도가 제한됩니다.

추천 인원

기본은 1인당 5명입니다. 25명 전원이 활동하면 각자 5명에게 추천하고 5명에게 추천받습니다. 교사가 전체 추천으로 바꾸면 각자 다른 24명에게 추천합니다.

자동 배정은 번호 순환 방식입니다. 결석자가 있으면 제출되지 않은 추천이 발생할 수 있습니다. 실수로 명단을 삭제하여 맞추기보다는 참여 상황에 맞춰 수업을 운영하세요. 별도 출석 체크·자동 결석 재배정은 제공하지 않습니다.

6. 수업 진행

  • 나의 선택: 학생이 200개 직업 중 하나와 이유를 제출합니다. 친구 선택은 아직 보이지 않습니다.
  • 친구 추천: 같은 반 친구들의 선택을 볼 수 있습니다. 배정된 친구에게 직업 1개와 이유를 추천합니다. 같은 친구에게 다시 제출하면 기존 추천을 수정합니다.
  • 추천 결과 공개: 자신이 받은 추천 수와 이유가 보입니다. 작성자 이름은 교사만 확인합니다.
  • 미래 탐구: 두 직업을 확정하고 현재 하는 일, 관련 과학기술, 미래 모습, 근거, 준비할 것, 자료 출처를 작성합니다.
  • 활동 마감: 학생의 모든 작성을 잠급니다. 결과 확인과 인쇄는 가능합니다.

처음 네 단계는 교사가 각각 열어 주세요. 학생은 진행 상태 새로고침으로 최신 결과를 불러옵니다. 단계 변경 알림은 약 20초 간격으로 확인합니다. 실시간 채팅처럼 모든 내용이 즉시 화면에 밀려오는 방식은 아닙니다.

희망 직업·미래 탐구는 입력을 멈춘 후 자동 임시 저장합니다. 제출 버튼을 눌러야 제출 완료로 표시됩니다. 친구 추천 이유는 제출 버튼을 눌러 저장합니다. 연결이 끊기면 저장 실패가 표시되므로 내용을 보존한 채 연결을 복구하세요.

미래 탐구의 두 직업 선정

  • 첫 번째: 내가 선택한 직업
  • 두 번째: 친구들이 추천한 직업 중 내 선택을 제외하고 추천 수가 가장 높은 직업
  • 동률: 동률 직업 중 하나를 학생이 선택
  • 다른 직업 추천이 없음: 나머지 199종 중 학생이 추가 선택
  • 확정 후에는 집계가 바뀌어도 탐구 직업을 자동으로 변경하지 않음

친구들이 가장 많이 추천한 직업이 내 희망과 같다면 일치 여부를 안내하고 다음 순위의 다른 직업을 탐구합니다.

추천 관리와 결과 저장

교사는 추천 내용 확인에서 작성자를 확인할 수 있습니다. 부적절한 추천을 비공개로 바꾸면 학생의 결과와 추천 수에서 제외됩니다. 학생이 해당 추천을 수정해도 교사가 다시 공개하기 전까지 비공개가 유지됩니다.

결과 모아보기에서 개인별 결과를 확인하거나 학급 전체 인쇄를 합니다. 인쇄 창의 대상에서 PDF로 저장을 고르면 PDF 파일을 만들 수 있습니다. CSV는 한글이 깨지지 않도록 저장하며 학생별 탐구 내용이 포함됩니다.

저장 방식과 운영 범위

  • 실제 수업 자료: Supabase에 저장, 다른 기기에서 이어 쓰기 가능
  • 체험 자료: 브라우저 로컬 저장, 실제 학급과 완전히 별개
  • 교사: 자신이 만든 학급만 관리
  • 학생: 자기 기록만 수정, 다른 학생의 탐구 내용은 열람 불가
  • 공개 범위: 같은 반의 제출된 희망 직업과 이유만 공유
  • 서버가 단계, 학급, 학생, 배정, 중복 추천, 입력 길이, 탐구 직업을 검사
  • 별도 실시간 구독, AI 대필, 파일 업로드, 학생 채팅은 없음
  • 아이콘은 기기 기본 그림 문자로 표시되므로 Windows·iPad에서 모양이 조금 다를 수 있음

검증 결과와 남은 확인

2026-11-13 기준:

  • 실제 macOS Chrome에서 200종 선택, 자동 저장·재접속, 단계 잠금, 추천 수정과 중복 방지, 결과 공개, 탐구 제출, CSV 다운로드 확인
  • 390px 모바일 폭에서 가로 넘침 없음 확인
  • PostgreSQL 호환 검증 환경(PGlite + pgcrypto)에서 3개 학급·75명, 125건 추천, 접근 권한, 집계, 익명 처리, 비공개, 접속 번호 제한·재발급·로그아웃 검증
  • 데이터베이스 검증은 로컬 환경입니다. 실제 Supabase 프로젝트, GitHub Pages 주소 및 75대 기기의 동시 네트워크 접속은 아직 검증하지 않았습니다.
  • 실제 Windows·iPad 기기에서는 아직 확인하지 않았습니다. 수업 전에 교사용 기기와 학생용 기기 2대로 접속·저장·공유를 확인하세요.

개발용 규칙 검사: Node.js 환경에서 node tests/core.test.cjs.

기존 40종 버전에서 200종으로 업데이트

  • 기존 config.js는 그대로 보관합니다. 새 ZIP의 config.js는 빈 설정 파일이므로 덮어쓰지 마세요.
  • Supabase SQL Editor에서 backend/upgrade-200-jobs.sql 내용을 실행합니다. 기존 학생과 선택·추천·탐구 기록은 삭제하지 않습니다.
  • GitHub의 index.html, jobs.js, core.js, app.js, style.css를 새 파일로 교체합니다. 나머지 안내·검사 파일도 함께 갱신해도 됩니다.
  • 배포 후 브라우저를 새로고침하고, 200번 직업인 ‘스포츠 트레이너’의 선택·저장을 확인합니다.

최초 설치라면 backend/setup.sql만 실행하면 됩니다. 기존 1~40번 직업 번호는 유지되어 과거 선택 기록이 다른 직업으로 바뀌지 않습니다. 학급 최대 인원과 추천 인원 제한은 그대로입니다.

200종은 분야별 25종으로 분류했습니다. 직업명뿐 아니라 설명과 관심 분야, ‘유튜버’, ‘AI’, ‘파일럿’ 등의 익숙한 표현으로 검색할 수 있습니다. 일부 아이콘은 여러 관련 직업에서 공통으로 사용하며 직업명을 함께 표시합니다.
